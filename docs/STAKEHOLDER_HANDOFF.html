Batjee / TradiGo Stakeholder Handoff

Prepared for non-technical review and project handoff

Executive summary: Batjee, branded in the interface as TradiGo, is a marketplace platform focused on local buying and selling in Pakistan. It already supports the full core journey from account creation, listing, browsing, and messaging through to moderation, seller ratings, support chat, and a structured transaction and platform-fee workflow for completed deals.
Marketplace Listings Buyer-Seller Chat Admin Moderation Seller Ratings Favorites Referrals Notifications Transaction Tracking

1. What This Product Is

The platform is designed as a local classifieds and marketplace product where sellers can publish ads and buyers can discover items, contact sellers, and complete deals. It is not just a listing board. It also includes moderation tools, support workflows, and internal controls that help manage quality and trust.

2. What Users Can Do

Account and onboarding

  • Create an account with name, email, password, and address details.
  • Log in and maintain a session in the app.
  • Join with a referral code from an invite link.

Buying experience

  • Browse active marketplace listings.
  • Search by keyword, category, and location.
  • Open a product page with images, pricing, seller details, and safety guidance.
  • Message sellers directly from a listing.
  • Save listings to favorites for later review.
  • Rate sellers after interacting with them.
  • Report suspicious listings or abusive sellers.

Selling experience

  • Post a new ad with title, description, category, price, and images.
  • See listing status inside a dashboard.
  • Track active, pending, inactive, and sold ads.
  • Share a personal referral code and referral link.
  • Manage deals through in-app chat and transaction steps.

3. How the Marketplace Works

Stage Business behavior
Listing creation A seller creates an ad with images and product details.
Moderation New listings do not go live immediately. They first enter a pending state for admin review.
Discovery Only approved active listings appear in the public marketplace.
Conversation Buyers and sellers communicate inside the app instead of outside channels.
Transaction The conversation can carry a structured deal amount, completion steps, and fee submission.
Completion Once both sides confirm completion, the listing is marked sold.

4. Messaging and Deal Management

Messaging is one of the strongest existing parts of the product. It lets buyers and sellers communicate directly inside the platform, which keeps engagement and trust-building within the app rather than sending users to external apps immediately.

  • Users can open conversations from product pages and seller pages.
  • Users can send both text and image attachments.
  • Unread counts are tracked and shown in the mobile navigation.
  • Support conversations with the admin team reuse the same chat system.

On top of chat, the platform includes a structured transaction layer. This allows both sides to confirm an agreed amount, mark a deal completed, and track the related platform fee before final administrative verification.

5. Admin and Backoffice Capabilities

The project already includes a working admin backoffice. This is important because the platform is not only user-facing; it also has internal tools to manage content, risk, and revenue-related workflows.

  • Approve or reject newly submitted listings.
  • Review and respond to support messages.
  • Inspect and resolve user-submitted abuse and fraud reports.
  • Verify platform fee payments attached to completed transactions.
  • Send in-app notification campaigns to users.
  • Apply promotional seller placements such as homepage or search boosts.

6. Trust and Safety Features

  • Listing moderation before public visibility.
  • Seller ratings and review comments.
  • Product and seller reporting flows.
  • Support chat with platform admins.
  • Account status control for inactive or suspended users.

7. Growth and Retention Features

  • Referral codes and invite links.
  • Favorites for saved browsing intent.
  • In-app notifications for announcements and campaigns.
  • Seller promotion placements to improve listing visibility.

8. Current Product Strengths

  • The core marketplace loop is already implemented end to end.
  • The product goes beyond simple listings by including trust, moderation, and support flows.
  • There is already an administrative path for revenue tracking through transaction fee verification.
  • The app includes both buyer-facing and seller-facing value, not just one side.
  • The dashboard, chat, ratings, reports, and notification systems create a strong base for growth.

9. Current Constraints to Know Before Launch or Scale

This section is intentionally business-oriented. These are the areas that matter most for launch planning, investor demos, or a future production hardening phase.
  • User password handling should be strengthened before a wider production rollout.
  • Admin access control is functional but should be hardened for long-term production use.
  • Realtime chat refresh works well for a single deployment instance but will need a more scalable architecture for larger traffic.
  • The admin dashboard exists today as a separate static backoffice interface, which is workable but not ideal for long-term maintainability.
  • The fee workflow is tracked inside the app, but it is not yet tied to a full payment gateway integration.

10. Recommended Next-Phase Priorities

Priority Recommendation Why it matters
High Harden authentication for both users and admins. Reduces security risk and improves production readiness.
High Add a production-grade realtime layer for messaging. Prepares the platform for scale and multi-instance deployment.
High Integrate real payment rails for platform fee collection. Turns fee tracking into a complete monetization flow.
Medium Rebuild the admin backoffice inside the main app. Improves maintainability, consistency, and future feature velocity.
Medium Add analytics and reporting dashboards. Supports product decisions, growth tracking, and stakeholder visibility.

11. Simple Stakeholder Takeaway

This is already more than a prototype listing site. It is a functioning marketplace foundation with moderation, trust features, messaging, dashboarding, referrals, notifications, and transaction governance. The main next step is not feature invention; it is production hardening, scaling decisions, and refinement of admin and payment infrastructure.
